# 须经用户确认的补充配置

配置ID：`qnxy-explicit-layout-v1`。

## 先读这一条

这里是**为排除排版自由度而明确提出的补充约束，不是原PDF逐字规定**。PDF明确规则见 `source-rules.md`，不受本配置更改。PDF未说明某项，不等于允许agent自由选择。

正式生成前，向用户提供本文并取得明确同意；没有同意就停止。不得把“按青年新语格式做”自行解释为已经同意本文。示例JSON故意保留未确认状态。若用户不同意，不得擅自改参数；应停止并请规范维护者发布另一个明确批准、带对应代码和测试的版本。不能为完成任务临时修改本skill。

建议一次询问：

> 原PDF未明确页边距、落款对齐及部分图表细节。是否同意本skill随附的 `qnxy-explicit-layout-v1` 补充配置（A4纵向、四边25.4毫米、正文首行两字、落款右对齐、图表及分页采用文中固定规则）？未同意前不会生成正式稿。

确认记录必须源于真实用户回复；不允许agent替用户同意。

## 固定补充参数

|项目|唯一允许值|代码落点|
|---|---|---|
|纸张|A4纵向，11906×16838 twip；原PDF页面约595.3×841.9pt，与A4相符|`qnxy.py`的`PAGE_W/PAGE_H`、`Builder.build`|
|页边距|上、下、左、右均1440 twip=25.4mm；装订线0；正文宽9026 twip|`MARGIN_X/MARGIN_Y/TEXT_W`|
|页眉/页脚距离|无页眉对象；页脚距页面底端720 twip=12.7mm|`Builder.build`|
|版式|全篇一个节、单栏、横排；无网格吸附；无首页特殊页码；正文和附件连续计页，自1开始|`Builder.build`|
|段前段后|所有段落均为0；禁止自动段前段后间距|`paragraph`|
|正文首行|2字符；PDF只明确要求两端对齐和28pt，本项为补充|`ROLES['body']`|
|四级标题|均28pt固定行距、两端对齐、无额外加粗；保持与下一段同页；只允许完整独立标题，不支持行内标题|`ROLES`、`paragraph`|
|大标题|独立1个段落，自动折行，不手动换行、不额外加粗；居中、不缩进|`ROLES['title']`|
|作者|最多1个个人名称段；可省略，不留空段占位；不缩进、无额外加粗|`Builder.build`|
|所有文字|黑色000000；正常宽度100%；字距0；不倾斜、不下划线、不上/下标；除表格第一行（表头行）外无任何加粗|`run_properties`|
|中西文空白|不手动添加中西文间距；关闭自动中西文、中文数字加空；正文只许内容所需的单个半角空格|`text`、`paragraph`|
|标题序号|每个父级下从1开始连续排列，上一级变化时下级重置；禁止跳级；最多四级，每级同父项下最多99项；附件内部另起标题序列|`heading_label`、`Builder.blocks`|
|落款|可省略；出现则必须为单位+日期两段，均右对齐、不缩进；输入真实ISO日期，输出“2026年10月28日”，不补零；不自动填当前日期|`Builder.build`|
|落款间隔|正文末段后恰好两个真实空段，每段固定28pt；与完整落款保持同页；不以56pt段前距冒充，不填空格。有落款时正文最后一块必须是普通正文段，不能以表格或图片结束|`Builder.build`、`validate_input`|
|附件|每个附件从新的一页开始；附件标记两端对齐；无空白页、无独立封面；正文和图表仍受同一规则控制|`Builder.build`|
|页码空一字|四号14pt字面宽，即14pt=280 twip缩进；不是半角空格，也不是正文16pt；破折号两侧各一个半角空格|`paragraph`、`Builder.footer`|
|表格结构|矩形、1行表头、1至6列、1至200正文行；不合并，不嵌套；整表居中，宽正文版心，等宽列（末列吸收twip舍入差）|`validate_blocks`、`Builder.table`|
|标题列判定|`row_header=true`表示首列为语义标题列，仅参与两字对齐，不加粗；`false`表示无标题列；两种取值下表头行以外都不加粗；不凭第一列位置自动猜测|`validate_blocks`、`Builder.table`|
|表格跨页|允许自然跨页；重复标题行；禁止单行跨页；不能容纳一行时停止，不缩小字体或横排|`Builder.table`+逐页复核|
|单元格|内边距四边80 twip=4pt；水平、垂直均居中；文字行距固定20pt；不设固定行高|`Builder.table`、`ROLES['cell']`|
|两字对齐三字|表头行或标题列中，单元格值恰为2个汉字的项目，自动插入一个U+3000全角空格，如“名称”→“名　称”；不处理普通数据单元格、长句或两个半角空格|`Builder.table`|
|表题/图注|固定16pt行距；首行和左右缩进均0；表题在表格正上方，图注在图片正下方，中间不另加空段|`ROLES['caption']`、`Builder.table/picture/blocks`|
|图表编号标点|`表1 名称`、`图1 名称`；标志字和序号之间无空格，序号与名称之间恰好一个U+0020半角空格；源PDF示例的数字间空白不作为额外格式授权|`Builder.table/blocks`|
|表号范围|全文包括附件连续编号，独立于图号；不手填表号|`Builder.table`|
|正文图号范围|全文及附件中的正文图片连续编号；不计入表格内图片|`Builder.blocks`|
|表内图号范围|原文“从所在表格标题行角度依次排列”未明确算法。本配置经确认后解释为：每张表分别从图1起，表头以下按行从上到下、同一行从左到右连续编号，不每行重置|`Builder.table`|
|正文图片的位置|所属标题后只能紧接1幅图，然后为图注，下一块必须为正文段落；保守限定以避免位置误判|`validate_blocks`|
|正文图片环绕|必须为`wp:anchor + wp:wrapTopAndBottom`，相对栏居中，相对锚定段落顶部；不允许嵌入型冒充上下环绕|`Builder.picture(floating=True)`|
|正文图片大小|等比；宽度不超过min(版心宽,7200 twip=127mm)，高度不超过5000 twip≈88.19mm，超出则等比缩小；不裁切、拉伸、加边|`Builder.image_geometry`|
|表内图片|`wp:inline`；整张表内所有图片显示宽高一致（比原文同排图片规则更严格），因而输入图片宽高比必须完全相同；水平垂直居中，宽不超过最窄列扣除8pt内边距；图注保留在同一单元格|`validate_blocks`、`Builder.table/picture`|
|图片承载段|不含任何文字。为了避免双重占位和裁切，承载段及绘图run的段落标记字体为仿宋1pt；正文浮图承载段固定1pt行距，表内图片承载段单倍行距由图高自动撑开。这个唯一的非正文技术例外不得用于任何可见文字|`Builder.picture`|
|图片内容边界|仅接收用户确认的PNG/JPEG，禁止截图正文来绕过文字字体规则；图片固有的颜色、图形不是公文文字样式授权，不能据此把正文变色。此版本不重绘图内文字，图内文字需用户自行确认|`image_spec`+逐页复核|
|空段|只允许落款前两个空段及必要的无文字图片承载段；其他位置不允许空段、手动换行、分页符堆叠|`validate_input`、确定性重建|

## 能力边界

本版本不允许封面、目录、摘要独立格式、红头、发文字号、密级/紧急程度版记、印章、水印、脚注、尾注、批注、修订、二维码自动生成、公式、代码块、超链接、艺术字、文本框、分栏、横向页面、五级标题、多级自动列表、斜线表头、合并表格、嵌套表格、表内多段正文、图文混合单元格、未知XML或任意用户自定义样式。

这不是认定这些格式在所有学校文件中都不合法；是说明本PDF和本skill没有提供足够依据，**因此本skill无权生成它们**。确实需要时停止，取得新的格式依据并由规范维护者升级，不得在当前版本临时放行。

不能承诺任意Office版本、任意字体缺失环境都呈现相同结果。能承诺的是：遵循本skill时，条件不满足不会发布“合格稿”。
